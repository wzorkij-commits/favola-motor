# Favola · живая сборка истории

Родитель пишет, что случилось. Через полторы минуты на полке стоит озвученная
иллюстрированная сказка про это, собранная из готового конструкта и прошедшая
проверки. Ничего не делается руками.

Это не демо: те же вызовы, те же промпты, те же проверки, которые пойдут в продукт.
Разница только в том, что конструктов шесть, а не сто.

---

## Как это устроено

```
запрос родителя
     │
     ▼
/api/triage    ── протокол раскрытия срабатывает ДО модели ──► экран с телефонами
     │            (насилие, принуждение, самоповреждение)
     │
     ├─ нет подходящего конструкта ──► «такой истории у нас пока нет»
     ▼
/api/story     ── модель наполняет конструкт (части 1–5 и три вопроса)
     │          ── часть 6 вставляется ДОСЛОВНО из клинической библиотеки
     │          ── guardrails: 11 проверок
     │          ── провал → перегенерация, до 3 раз
     │
     ├─ три раза не прошло ──► история не показывается, уходит на вычитку
     ▼
/api/image ×6  ── иллюстрации, утверждённый стилевой блок
/api/voice ×7  ── шесть частей и вопросы, Style = 0
     ▼
объект формы STORIES → STORIES.push(story) → полка
```

Пайплайн разбит на короткие вызовы намеренно: серверная функция Vercel не переживёт
шесть картинок и семь дорожек в одном запросе. Дирижирует клиент — и заодно получается
честный прогресс на экране сборки, а не крутилка.

## Сказка, версия 2 (19 сентября 2026)

Путь сказки теперь такой: `/api/triage` заполняет досье случая (что случилось, чего хотел ребёнок, неверный вывод, инструмент и его ручка, детали запроса, план) и выбирает варианты и уроки; `/api/story` пишет две половины (`part: "a"` части 1–3, `part: "b"` части 4–5 с вопросами и кадрами), каждая укладывается в 60 секунд; `/api/polish` правит точечно и возвращает только изменённые части.

Где что лежит: Библия в `lib/bible.js` (читаемая версия с объяснениями лежит в проекте на claude.ai), библиотека инструментов в `data/tools.json`, библиотека уроков из книг в `data/lessons.json`, образец голоса в `data/sample.json`, разнообразие (имена, помощник, форма, начало, юмор) в `lib/variety.js`, выбор уроков в `lib/lessons.js`. После правки любого `data/*.json` выполнить `npm run data`. Без `part` и без досье `/api/story` пишет всё целиком, как раньше (прежний клиент работает).

Тесты без ключей: `node scripts/story-test.mjs` (подмена ответов модели).

## Два решения, которые здесь важнее кода

**Шестая часть не генерируется.** «Когда звать взрослого» — единственная часть, за
которую продукт отвечает всерьёз. Она выбирается целиком из `data/panel6.json` по ключу
«тема × возраст» и вставляется дословно. Проверка `panel6-verbatim` сравнивает результат
с библиотечным текстом и роняет историю при любом расхождении.

Отсюда следует то, что нельзя купить за деньги: **можно показать регулятору конечный
список всего, что ребёнок может услышать в самом опасном месте истории.** Ни одна
модель этот текст не трогает.

**Протокол раскрытия стоит перед моделью.** Список признаков в `api/triage.js`
проверяется по сырому тексту родителя. Совпало — запрос до генерации не доходит,
показывается экран с телефонами доверия. Это то, что обещано на слайде про данные
и безопасность.

## Проверки

`lib/guardrails.js`, 11 правил. `hard` роняет историю, `soft` помечает на вычитку.

| правило | уровень |
|---|---|
| ни одной цифры и характеристики про тело | hard |
| внешность не как проблема и не как достоинство | hard |
| никаких методов самоповреждения | hard |
| ни одно мировоззрение не названо правдой или выдумкой | hard |
| инструмент не обещает исчезновения | hard |
| часть 6 совпадает с библиотечной побайтно | hard |
| финальная строка на месте | hard |
| ровно шесть частей и три вопроса | hard |
| вопрос отвечаем взрослым, а не допрос | hard |
| взрослый не спасает и не наказывает | soft |
| объём 500–1000 слов | soft |

Проверить проверки, без ключей и без единого запроса к провайдеру:

```bash
npm run check
```

Первая половина проверяет, что каждый файл вообще импортируется — синтаксис ловит не всё,
а функция на Vercel падает ещё до первого запроса. Вторая гоняет guardrails на заведомо
плохих историях.

## Как вставить в прототип

1. Залить эту папку отдельным проектом на Vercel — получится, например,
   `favola-api.vercel.app`.
2. В `index.html` прототипа, перед `</body>`:

```html
<script>window.FAVOLA_API_BASE = 'https://favola-api.vercel.app';</script>
<script src="https://favola-api.vercel.app/favola-live.js"></script>
```

3. Туда же вставить содержимое `web/request-screen.html`.
4. Показать экран там, где сейчас стоит выбор темы:
   `document.getElementById('fv-live').hidden = false;`

Ничего в существующем коде переписывать не нужно: модуль собирает объект той же формы,
что элементы `STORIES`, и делает `STORIES.push`.

**Про грабли из файла прототипа.** Правки по строкам дважды уносили соседний код,
поэтому здесь ничего не вырезается — только два тега `<script>` и один блок разметки.
Проверять надо запуск, а не синтаксис: открыть, отправить запрос, дослушать до конца.

**Ночные версии, обложка и карта речи** делаются существующим кодом приложения.
Модуль вызовет `makeNightVersions`, `makeCover`, `buildSpeechMap`, если они объявлены
глобально; если имена другие — поправить три строки в конце `favola-live.js`.
Без них история всё равно играет, просто без ночного режима.

## Что здесь ещё не настоящее

**Клиническая подпись.** Все шесть текстов части 6 стоят с `clinical_review: "pending"`.
До пилота под каждым должна быть фамилия и дата. Это единственное, что нельзя обойти.

**Шесть конструктов вместо ста.** Написаны по четырём готовым сказкам, «Барабанщику»
и одному новому. Остальные девяносто четыре — то, на что просятся деньги раунда.

**Персонаж не держится между кадрами.** Лист персонажа передаётся текстом, этого мало:
в продукте нужен либо референсный кадр на вход, либо одна модель с поддержкой
консистентности. Заметно на третьем-четвёртом кадре.

**Словарные проверки ловят формулировку, а не смысл.** «Она весила сорок килограммов»
поймается, обходной пересказ — нет. Поэтому в пилоте вычитываются все сто историй:
каждая пойманная руками формулировка становится новым правилом здесь.

---

## Что меряет пилот

Каждая собранная история пишет в `_meta`: конструкт, id текста части 6, число попыток
и полный отчёт проверок. Из ста историй получаются два числа, которые назначают цену
следующему раунду:

- **какая доля прошла проверки без правок человека** — работает ли система;
- **какая доля родителей дошла до разговора после сказки** — работает ли продукт.

## Живой ли пайплайн

Открой в браузере `https://твой-адрес.vercel.app/api/ping`. Страница скажет,
какие ключи заданы, сколько конструктов и текстов части 6 загружено, и готова ли
система собирать сказки. Это единственный адрес, который открывается глазами:
остальные принимают запросы только от приложения.
